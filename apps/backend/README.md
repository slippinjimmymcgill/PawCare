# PawCare Backend (FastAPI)

Scaffolded in `P1-BE-001` (Phase 1, Sprint Block 1-2). Structure only — see
`../../task_backlog.md` §3.1a for the task spec, and
`../../docs/ops/local-dev-setup.md` for full environment setup.

## Quick start

```bash
cp .env.example .env    # then edit SECRET_KEY / JWT_SECRET_KEY
python -m venv .venv
source .venv/bin/activate   # .venv\Scripts\activate on Windows
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Verify: http://localhost:8000/health → `{"status": "ok"}`
Interactive API docs (auto-generated by FastAPI): http://localhost:8000/docs

## Layout

```
app/
├── main.py           # FastAPI app, CORS, /health
├── core/
│   └── config.py     # Settings (reads .env)
├── api/v1/            # One router module per feature area, each a stub
│   ├── router.py       #   today (/ping only) — real logic lands with
│   ├── auth.py          #   each feature's own task (see each file's
│   ├── pets.py           #   docstring for which task fills it in).
│   ├── records.py
│   ├── assessments.py
│   ├── assistant.py
│   ├── reminders.py
│   └── admin.py
└── schemas/           # Pydantic request/response models, one file per
    └── ...              # entity (requirements.md §5) — also placeholders.
```

No database models live under `app/` yet — `docs/design/models/*.py`
(from `P0-BE-001`) is the reviewed draft schema; wiring it into this app
with real Alembic migrations is `P1-BE-002`, not this task.
